
# Codex Project Instructions

## Design Standards

Before making any frontend changes, read `DESIGN_SYSTEM.md`.

All interfaces must follow the project's design system.

## UI/UX Rules

- Build professional, modern, production-quality interfaces.
- Avoid generic AI-generated website designs.
- Do not automatically use purple gradients, oversized hero sections, or excessive rounded cards.
- Prioritize visual hierarchy, typography, spacing, usability, and accessibility.
- Use consistent components throughout the application.
- Design for desktop, tablet, and mobile.
- Follow existing design patterns unless explicitly asked to redesign them.
- Never introduce random colors, fonts, or spacing values.
- Use subtle animations and meaningful interactive feedback.
- Include loading, empty, error, and success states where appropriate.

## Implementation

- Reuse existing components before creating new ones.
- Respect the project's framework and installed dependencies.
- Avoid unnecessary UI libraries.
- Keep components maintainable and reusable.
- Check responsiveness and accessibility.
- Run available lint, typecheck, and build commands after changes.

## Design Review

Before finishing any frontend task:
1. Verify consistency with DESIGN_SYSTEM.md.
2. Check responsive layouts.
3. Check visual hierarchy and alignment.
4. Check hover, focus, and disabled states.
5. Fix obvious design inconsistencies.
